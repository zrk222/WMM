# Reusing WMM's agent harness for bounded marketing work

WMM keeps generated proposals separate from execution authority. These
refinements reuse its current draft validator, exact approval envelope, durable
jobs, native inference host, usage receipts and personal-agent guide. No second
agent framework, new package, new operation name or provider connection is added.

## Content repurposing with the existing copy task

Read `operations.read` through the existing CLI or MCP discovery path. The
hash-bound `personal_agent_guide.owner_operating_protocol` now contains
`draft_output_contract` and `draft_recipes`. The content-pack recipe names the
existing `original_copy` task and supplies its exact `focus` text.

In **Your agents**, choose **Draft original copy**, use that focus text and review
the proposed transmission through the existing approval flow. The same task and
focus work in native owner-approved inference. A personal agent can guide these
steps using its demonstrated host capabilities; discovery adds no new model-call
tool or permission. Do not invent an operation name to bypass owner review.

An accepted pack contains these eight items in order:

1. Carousel outline.
2. Email draft.
3. Blog outline.
4. Three separate social posts.
5. Two separate ad angles.

The runtime requires every exact item title, nonblank text and approved source
references. Missing, duplicated or reordered items fail acceptance. All text
still passes the existing size and citation-scope checks. Editing the recipe's
focus text makes it an ordinary copy request, without a complete-pack claim.

These are concise text drafts and outlines. They are not full-length articles,
rendered visuals, videos, sent email or published posts. Structural validation
does not establish factual accuracy, rights or business lift. Unsupported facts
belong in `unknowns`; the owner still reviews the claims.

## Tighter contracts and safer reuse

The runtime exposes and reuses the same draft limits in its prompt and validator:
eight items, eight unknowns, summary/detail up to 1,200 characters, title up to
160 characters and each unknown up to 500 characters. Provider-facing JSON schema
remains the existing portable subset; WMM does not assume that every compatible
endpoint supports extra schema keywords.

Approval freezes the output-contract hash and selected recipe. A changed contract
or recipe stops queued work before another model request. Old pending approvals
without that binding require a new preview; they are not silently upgraded or
replayed. The existing no-replay rule for uncertain model calls remains intact.

The native proposal prompt now puts approved context and operation contracts
before the changing task focus and feedback. Changing focus changes the exact
approval hash while retaining the reusable prefix. A cache match never renews a
grant, approves a tool or establishes current source access.

DeepSeek-reported `prompt_cache_hit_tokens` is normalized to
`cache_read_tokens`; `prompt_cache_miss_tokens` is stored separately as
`cache_miss_tokens`. A miss is not a cache write. Malformed or conflicting aliases
remain explicit telemetry issues; absent totals and prices remain unknown. WMM
does not infer financial savings from these counters.

## Disposition of the supplied architecture reports

| Recommendation | WMM treatment |
| --- | --- |
| Model proposes; runtime controls effects | Existing approval/grant/operation boundaries retained. |
| Typed outputs and bounded generation | Shared runtime limits added to the current draft contract and prompt. |
| Multi-channel content multiplier | Eight-item text recipe added to the existing copy workflow. |
| Cache-efficient context | Existing desktop prefix retained; native prefix improved; DeepSeek hit/miss receipts added. |
| Durable checkpoints and idempotent work | Existing jobs/checkpoints retained. Uncertain inference is not automatically resent. |
| Review compilation/join barrier | Complete-pack acceptance added for this single request. Existing sequence aggregation remains separate; no new parallel-agent scheduler is claimed. |
| Brand memory | Existing app facts, source snapshots and advisory creative taste reused. No unverified memory graph added. |
| Automatic fact checking or confidence-based approval | Not claimed. Valid citations do not prove a claim; model scores grant no authority. |
| Verified-buyer badges or testimonial reuse | Never inferred from raw review text. Existing provenance and rights checks still apply. |
| Thirty-concept walls, cinematic pages, automatic lead interception | Not implemented by this bounded refinement. Existing briefs/editors remain the production routes. |
| Automatic competitor scraping or new schedules | Not enabled; existing permitted discovery, schedules and approval boundaries remain authoritative. |
| Blanket draft-only publishing ban | Applies to this generated pack, not a removal of WMM's separately approved execution paths. |
| Three retries for every provider error | Not adopted. An uncertain request may already have consumed allowance. |
| Persisted internal reasoning | Not adopted. WMM retains allowed outputs, source references and receipts, not a requested reasoning chain. |

The reports' timing comparisons and promised marketing performance are not WMM
measurements. Identical input structure does not guarantee identical model text.
No provider was called with a real account to establish cache hits or savings.

## Primary references checked

- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): a rapidly changing developer-preview plugin harness. Its documented npm entry is `npx @deepseek-ai/dsh web`; this refinement does not install or run it.
- [Harness architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md): plugin composition and scoped execution are relevant patterns; the reports' named marketing departments are not established as WMM integrations.
- [DeepSeek JSON output](https://api-docs.deepseek.com/guides/json_mode/): valid JSON still needs application validation, and blank/incomplete output requires explicit handling.
- [DeepSeek context caching](https://api-docs.deepseek.com/guides/kv_cache/): prefix reuse and reported hit/miss counters are distinct from generated-output randomness and measured cost savings.
- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence): checkpoints and long-term stores have distinct roles. WMM retains its existing persistence rather than adding this dependency.

## Owner shortcuts

In desktop Agent work or native Agent drafting, choose **Use eight-piece content pack**. It fills the existing original-copy task and exact focus. It does not submit, create a job, select a different provider or approve charges. Review the exact prompt and approve through the existing workflow. Agents can discover the same recipe in the personal-agent guide; this does not add a model-call CLI/MCP operation or publishing authority.

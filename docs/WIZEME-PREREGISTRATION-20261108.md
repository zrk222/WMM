# WizeMe organic tracking test: preregistration packet

**Status: DRAFT FOR OWNER REVIEW — not registered, not executed, no result.**
Prepared 2026-11-08 (UTC) for the next proof in
[WIZEME-DOGFOODING.md](WIZEME-DOGFOODING.md): one organic post with a unique
campaign link, frozen measurement window, sample requirement and decision rule.

This packet is an owner worksheet. It is not a WMM study record, not approval,
and not evidence. The owner registers the study and executes the post through
their normal WMM flows. No agent may publish, spend or widen authority from this
document.

## 1. Scope

Prove that one unique campaign tag survives from the approved post through the
landing page to the registration record that WMM can observe. This is
**attribution feasibility only**. It does not measure installs, activation,
paid conversion, revenue, retention, lift or time savings, and it is not a
holdout comparison.

- One app, one release, one locale, one landing path, one creative.
- One organic post. No paid spend. Default `spend_minor` stays 0.
- The study window ends at the frozen time; it is never extended.

## 2. Authority and boundaries

| Item | Value |
| --- | --- |
| Owner approval to execute | `OWNER_INPUT` (exact post text, destination, account, time) |
| Paid spend | None; `spend_minor = 0` |
| Provider writes | None beyond the single approved organic post |
| Publication receipt to retain | Exact provider post ID and permalink |
| Source of events | Private authenticated owner collector only; no public ingestion endpoint |
| Credentials | Owner's current scoped connections; never copied into this packet |

Agents may prepare and read within a current grant. They may not create or widen
the grant, approve the post, or claim a result.

## 3. Frozen registration fields

Fill every row before registering. WMM rejects a window shorter than 1 second
after registration or longer than 30 days.

| Field | Value |
| --- | --- |
| App | WizeMe.APP (`OWNER_INPUT: app id`) |
| Release / version | `OWNER_INPUT` (current promoted release) |
| Locale | `OWNER_INPUT` |
| Origin | `OWNER_INPUT` (registered HTTPS website, no query or fragment) |
| Landing path | `OWNER_INPUT` (path only, same origin, no query, no `..`) |
| `utm_source` | `facebook` (or the exact supported network used) |
| `utm_medium` | `organic` (fixed by WMM) |
| `utm_campaign` | WMM-issued study UUID (do not invent) |
| `utm_content` | `OWNER_INPUT` (opaque creative/source ID, `[A-Za-z0-9_-]{1,128}`) |
| `starts_at` | `OWNER_INPUT` (UTC, at least 1 second after registration) |
| `ends_at` | `OWNER_INPUT` (UTC, `starts_at` < `ends_at`, window ≤ 30 days) |
| Registration time | Set by WMM at `register`; never backfilled |

The canonical link is generated by `tagged_url()` in
`mission_control/observational_campaign_contract.py` and has exactly four query
keys in that order:

```
https://<origin><landing_path>?utm_source=<source>&utm_medium=organic&utm_campaign=<study_uuid>&utm_content=<creative_id>
```

Use the generated string unchanged. Do not add, reorder, re-encode or strip
parameters. Do not use the funnel destination validator as a substitute for
the study's exact-match check.

## 4. Primary measure and denominator

| Item | Definition |
| --- | --- |
| Unit | One distinct pseudonymous subject |
| Eligible landing | `LANDING` event with the registered `campaign_token`, inside the window, consent `GRANTED`, `bot` false, `internal_test` false |
| Linked registration | `REGISTRATION` for the same subject with an earlier eligible `LANDING` by report `as_of` |
| Denominator | Eligible tagged landings in the same window |
| Report scope | `ATTRIBUTED_DESCRIPTIVE_ONLY`; no install, revenue, lift, winner or causal field |
| Unknown handling | Denied/unknown consent, `bot` true or null, internal tests, missing/invalid token, unmatched registrations and duplicates are reported as separate exclusions, not folded into zero |

Observed zero is allowed only when the source supplied complete coverage for
that event type. Otherwise the count is null.

## 5. Sample requirement (owner-set, pre-registration)

Set these before exposure and do not change them mid-window:

| Item | Draft rule | Value |
| --- | --- | --- |
| Minimum eligible tagged landings | At least 3× the minimum linked registrations | `OWNER_INPUT` |
| Minimum linked registrations | At least 10% of the E12 30-day baseline registrations, rounded up, minimum 10 | `OWNER_INPUT` |
| Coverage | `complete: true` for both `LANDING` and `REGISTRATION` in the final batch | Required |
| Window maturity | `observed_at` after `ends_at` | Required |

The E12 baseline values are owner-private and intentionally absent from this
repository. Deriving the numbers from them is the owner's step, not an estimate
in this packet. If the baseline cannot be recovered, mark the sample
requirement `UNSET` and expect an inconclusive result instead of lowering it.

## 6. Decision rule (descriptive, not lift)

Evaluate once, after `ends_at`, with a `report` whose `as_of` is after the
window. One outcome, recorded with its receipt:

| Outcome | When | Next action |
| --- | --- | --- |
| `TRACKING_VERIFIED_CONTINUE` | Tag present on eligible landings, registrations linked to earlier eligible landings, both coverages complete, both minima met | Keep the tag convention; plan a separate, approved follow-up |
| `TRACKING_BROKEN_REVISE` | No tagged landing, token missing, or registrations not linked to an earlier eligible landing | Stop; repair site capture or event mapping; register a **new** study before retrying |
| `COVERAGE_INCOMPLETE_COLLECT` | Counts null or coverage incomplete/null, with traffic present | Keep the window closed; repair the collector and re-read the same window or register a new study |
| `INCONCLUSIVE_STOP` | Sample minimum not met, exclusions dominate, or source cannot reproduce the window | Stop; do not reinterpret the existing data as a result |

No arm comparison, no lift interval, no install or revenue inference. A
successful `TRACKING_VERIFIED_CONTINUE` says the tag reached the records; it
does **not** say the post caused growth.

## 7. Stop rule

- The study ends at the frozen `ends_at` and is not extended.
- No early peek that changes scope, sample or decision rule.
- No second post inside the window.
- If the tag is absent or the token is not persisted, stop and revise; do not
  add a second tag to the same study.

## 8. Evidence to retain

1. Study registration receipt: study UUID, definition hash, registered time.
2. The exact generated tagged URL.
3. Publication receipt: provider post ID, permalink, approved content hash.
4. Each ingestion batch: `batch_id`, `study_hash`, `source_id`,
   `source_receipt_sha256`, `observed_at`, coverage, event/receipt hashes.
5. The report: `as_of`, distinct-subject counts, exclusions, coverage, hashes.
6. Any correction record referencing the original event ID and hash.
7. The recorded decision, appended to the dogfooding record with UTC time,
   authority, actual result and next decision.

## 9. Owner execution checklist

1. Recover the E12 baseline and set the two sample minima above.
2. Confirm current app release, locale, origin and landing path.
3. Register the study through WMM and copy the generated tagged URL unchanged.
4. Approve the exact post text, destination, account and time.
5. Publish the single organic post and save its provider ID/permalink.
6. After `ends_at`, export landing and registration events from the private
   authenticated source and ingest them with explicit coverage.
7. Read the report; if coverage is incomplete, repair and re-read or register
   a new study.
8. Record `TRACKING_VERIFIED_CONTINUE`, `TRACKING_BROKEN_REVISE`,
   `COVERAGE_INCOMPLETE_COLLECT` or `INCONCLUSIVE_STOP` with the receipts.

## 10. Non-goals

Installs attributed to the post, activation, paid conversion, revenue,
retention, causal lift, notification delivery, ad spending, time savings and
any claim that the tag "worked" beyond reaching the records.

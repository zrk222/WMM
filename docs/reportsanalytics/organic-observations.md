# Organic publication observations

Each publication receipt can retain the latest provider observation, including `metrics.source`, `scope`, `unit`, `counts` and the UTC time at which the API response was interpreted. A count belongs to one provider video or media item; it is not a denominator for conversion, unique reach, install attribution, revenue, or growth. Missing values remain null and do not mean zero. Data may be delayed or revised by the provider. The receipt also distinguishes processing, provider publication readback, privacy, and independently verified public visibility.

- YouTube uses `videos.list` statistics (`viewCount`, `likeCount`, `commentCount`) for the exact video and verifies the channel ID. Google describes these fields in the [Videos resource](https://developers.google.com/youtube/data/reference/rest/v3/videos); the meaning of view count can change under provider rules. Shorts classification and public visibility remain separately unverified by these metrics.
- TikTok publication-status reads do not contain engagement counts. After the provider returns exactly one public post ID, a subsequent bounded `video/query` read requests the matching ID and view, like, comment and share counts, subject to `video.list` permission. The [TikTok v2 query contract](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-query) verifies video ownership for the authorized user. If no single public ID is available, counters stay null rather than being inferred.
- Instagram media read requests `like_count` and `comments_count`; view count remains null because Insights is not requested. The selected Page and Instagram account are checked separately. Meta's [official Business SDK IGMedia definition](https://raw.githubusercontent.com/facebook/facebook-python-business-sdk/main/facebook_business/adobjects/igmedia.py) lists both fields and supports selecting fields on GET. This establishes the SDK field names, not whether a particular app, account or token may access them. Validate permission and provider-version compatibility with Meta before a release or live claim. A denied read is an error, never a zero count.
- LinkedIn counters are not supplied by these adapters. Member read permissions can be restricted and organization statistics need additional role and permission; no unobserved metrics are fabricated.

These are provider API observations, not evidence that a campaign caused app installations, purchases, revenue or any other downstream result. No provider data was collected in the fixture tests.

## Retained history
Each successful provider read retains its sanitized state in the immutable receipt chain. The private JSON report includes receipt-bound metric_history samples as well as the latest observation. Later reads and retirement of protected upload-session checkpoints do not erase earlier observed counts. These samples are engagement observations, not causal app outcomes.

# Personal agents operating WMM

Read `operations.read` (CLI) or `wmm_operations_read` (MCP) for the current
`personal_agent_guide`. The same guide is available at the existing app-owned
`/api/apps/{app_id}/agent-operations` HTTP route. Its app, policy, catalog and guide
hashes bind the instructions to current context. Discovery performs no provider
connection, credential loading or agent invocation. Live acceptance for all six
named personal-agent profiles remains NOT_RUN.

## Portable operating brief

The app-bound guide now includes `owner_operating_protocol`: an outcome brief,
Socratic decision method, nine-stage operating cycle, creative eligibility rules,
resource limits and a private owner-report structure. Use this same protocol from
`operations.read` in CLI, MCP or the admitted in-process client. It is guidance;
the actual grant, current source versions and runtime checks govern execution.

Lead the owner's report with the result and one next useful action.

Read `report.read` (CLI/in-process) or `wmm_report_read` (MCP), with empty input
and an app-scoped grant permitting that read. It returns the same consolidated
analytics projection as native Results & reports: `appID`, `sourceHash`,
`observedAt` and allowlisted metric rows. Cite each row's evidence and preserve
null observations as unknown. Provider aggregates and Apple downloads remain
separate from transaction evidence and causal attribution. This read never
publishes or authorizes delivery to another person.

Include:

- What ran, its current stage, receipt/job ID, artifact and readback time.
- The primary KPI, baseline, observed value, numerator/denominator, window,
  source, coverage and attribution limits; use null plus a reason when unknown.
- Actual costs, calls and tokens where available, with currency and budget
  remaining; keep projected savings separate from actual usage.
- The exact decision or approval needed, recommended option and remaining work.

Report in the owner conversation or an authorized private destination. A report
instruction does not send a message or create a schedule. Never include secrets
or another app's data. Mark the scope accurately: research complete, render
complete, publication verified and measured app results are different outcomes.
Viral-only research requires **100,000 views AND 10× a documented creator
baseline**; missing baselines remain candidates. User UGC intake is exempt from
that discovery filter, while production still requires current reuse rights.

1. Read current workspace, policy, catalog and saved evidence. Use the guide's
   exact app/version/hashes. The guide embeds actual `creative_taste` policy,
   its policy hash, five laws and app-bound public preferences for the Prestige
   taste handoff. It remains ADVISORY_ONLY and execution integration remains
   REQUIRED_NOT_COMPLETE; retain audience, intent, references and constraints.
2. Test assumptions against sources. Ask only material questions that remain
   after context review, at most three concise questions. Mark hypotheses and
   unavailable or conflicting evidence.
3. Execute relevant implemented catalog workflows within current grants and
   checkpoints. Use exact saved inputs and current readback. Continue independent
   permitted work when another path is blocked. The dynamically returned
   `unimplemented_execution` list remains implementation work.
4. Preserve maker/checker review and standing authority limits. Never self-approve.
   UNKNOWN requires inspection/reconciliation and no automatic mutation resend.
   Queued is not completed and prepared is not published.
5. Return COMPLETE, FAILED, BLOCKED or UNKNOWN, with app/version/hash scope,
   operation, request key or receipt ID, input/output hashes, timestamp with time
   zone, readback, artifact/source links, source KPIs and remaining limits. Use
   null plus an explanation for unavailable evidence; invent no KPI or receipt.

Provider permissions, memory, instructions and skills do not grant WMM authority.
The local server remains authoritative. This guide does not install a connector,
schedule a task, contact an agent or implement every product workflow.

## Native standing video scope

In the iPhone/iPad app, the owner can select **On-device iPhone/iPad video
production** in standing controls after connecting and testing a protected
inference profile. Review the exact operations, expiry and call/concurrency
limits before switching the scope on. This scope uses existing local editor,
scene and timeline operations; it does not authorize desktop renderers,
publication or paid provider effects.

Keep the saved job identity when a render is interrupted. Pending native renders
occupy the approved concurrency allowance until completed or cancelled. Turning
the scope off cancels its pending native jobs. Source access and decoded-output
commit recheck the originating execution, current scope, grant and protected key.
Previously completed owner artifacts remain available with current source/rights
checks. Report those output receipts separately from publication or measured app
sales. The configured Agent work screen still requests confirmation for each
model transmission; a local standing scope does not remove that requirement.

## Official sources reviewed

Profiles reviewed on 2026-10-28 also cover **Codex / ChatGPT Dots** and
**Claude Duet**. Dots can coordinate a task on a connected computer; first verify
WMM on that exact computer and pass the child explicit app/hash/operation scope.
Duet uses a cloud computer; do not assume Claude Code or Chrome connectivity
applies to it. Neither profile claims this installation is connected.

Each profile exposes a `wmm_runbook` with context setup, first connection check,
handoff method and owner reporting instructions. Other agents use the shared
protocol after demonstrating execution location, transport and current access.

For a team, appoint one coordinator. Give researchers, creatives, operators and
analysts bounded responsibilities and only the permissions each needs. Pass
app/version/hashes, resource revisions, limits, receipts, unknowns and next actions
with every handoff. Parallelize independent reads and serialize changes to the
same resource. An agent reviewer cannot replace a required authenticated human
checker. The coordinator reconciles child evidence and sends one owner summary;
a child finishing its assignment does not prove the whole goal is complete.
